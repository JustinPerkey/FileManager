# M4 — Values, field rules, durations, validation, and shared vectors

Status: approved (2026-11-17; revised 2026-11-16: duration kind)
Project: dbmanager   Depends on: M1 (landed), M3 (landed)

## Goal

Define the boundary value type `DbValue`, the field kind and rule types
(including durations), and the pure, authoritative `validate` function.
Publish them, together with M3's diagnostic, mode and unit types, to
`lib/generated/`. Write the shared validation vectors that the TypeScript
mirror (a later milestone) must also pass.

## Context

The Database Manager (`dbmanager`) edits rows of a user's SQLite database as
objects. It also edits the extra columns of many-to-many links ("link
fields"), which follow the same rules. Each editable field has a **kind**
and **bounds** from the TOML config. Kinds, bounds, boolean storage and the
duration format are specified in `docs/dbmanager-config.md`, written by M3.
Read its "Fields", "Kinds" and "Durations" sections before starting.

This milestone turns a field's resolved rule plus a user input into either
the value to store or a list of issues. Resolving rules from config and
schema is M5, so here `FieldRule` is plain data.

Validation is **authoritative in Rust and mirrored in TypeScript** for
inline feedback. The rule data (`FieldRule`) is generated by ts-rs, so it is
defined once. The logic is mirrored, and **parity is proven by data**:
`examples/dbmanager/validation-cases.json` is run by a Rust test here and by
a vitest test later. Every case must therefore be decidable without a
database, and its normalised result must be reproducible in TypeScript.

Builds on:

- M1: `crates/fm-dbmanager` (`db.rs`, `state.rs`).
- M3: `crates/fm-dbmanager/src/config/`, which provides
  `ConfigDiagnostic`, `DiagnosticSeverity`, `TableMode`, `FieldMode`,
  `RelationMode` and `DurationUnit` (`Milliseconds | Seconds | Minutes |
  Hours | Days`), all deriving `ts_rs::TS`. If M3 wrote a duration grammar
  parser in `src/config/`, move it into `src/rules/duration.rs` and reuse it.

Rules that bind this task:

- No tauri in the crate. fmt and clippy pedantic clean. Use only a scoped
  `#[expect]`.
- A boundary type is defined once in Rust (`#[derive(ts_rs::TS)]`).
  - It is exported only through `apps/desktop/src-tauri/src/generated_types.rs`:
    add it to the `EXPORTERS` list, then run the regenerate command in
    `CLAUDE.md`.
  - Never hand-edit `lib/generated/`. Never use `#[ts(export)]`.
- **No `bigint` in generated TS** (`generated_types_have_no_bigint` fails).
  Integers, reals and durations cross as **strings**. Sizes and counts are
  `u32`, or `u64` with `#[ts(type = "number")]`.
- Generated file names are type names. Do not reuse a name already in
  `apps/desktop/src/lib/generated/` (`Diagnostic`, `Severity`, `FileSlot`
  and `EntryView` exist, for example).

### `DbValue` (`src/value.rs`)

`#[derive(Clone, Debug, PartialEq, Eq, Serialize, Deserialize, ts_rs::TS)]`,
`#[serde(tag = "type", content = "value", rename_all = "camelCase")]`. JSON:

```json
{"type":"null"}
{"type":"integer","value":"42"}
{"type":"real","value":"1.5"}
{"type":"text","value":"abc"}
{"type":"duration","value":"1h30m"}
{"type":"blob","value":{"size":1024}}
```

- **From a stored value** (`rusqlite::types::ValueRef`):

  | Storage class | Becomes |
  | --- | --- |
  | integer | a decimal string |
  | real | Rust's `f64` `Display` |
  | text | a string (lossy UTF-8) |
  | blob | its length only; contents never cross the boundary |

  Storage never yields `duration`. The read layer (M6) turns an integer in a
  duration field into `Duration` with `duration::format`.
- **To a bound parameter:** only **after** `validate` has normalised the
  value, through `fn to_sql(&self, rule: &FieldRule) -> rusqlite::types::Value`:

  | Kind | Bound as |
  | --- | --- |
  | integer, bool | `Integer(i64)` |
  | real | `Real(f64)` |
  | text | `Text` |
  | duration | `Integer(count)` in the rule's unit |
  | null | `Null` |

  A blob is never converted, because v1 never writes one.

### Durations (`src/rules/duration.rs`)

```rust
pub fn parse(text: &str, unit: DurationUnit) -> Result<i64, DurationError>;  // count of `unit`
pub fn format(count: i64, unit: DurationUnit) -> String;                      // canonical
pub enum DurationError { Grammar, Overflow, Precision }
```

- **Grammar:** an optional `-`, then either a bare integer (a count of
  `unit`) or one or more components `<digits><suffix>`.
  - Suffixes are `d`, `h`, `m`, `s` and `ms`, lowercase, in strictly
    decreasing order.
  - Components may be separated by exactly one ASCII space.
  - Nothing else is accepted: no leading or trailing spaces, no empty input,
    no decimals.
- **Arithmetic:** compute the total in milliseconds as `i128`
  (`d` = 86 400 000, `h` = 3 600 000, `m` = 60 000, `s` = 1 000, `ms` = 1).
  It must be a whole multiple of the unit, or the error is `Precision`. The
  resulting count must fit `i64`, or the error is `Overflow`. A bare integer
  is already a count, and must fit `i64`.
- **Canonical:** the sign, then the non-zero components from `d` down to the
  unit's own suffix, with no spaces. Zero is `0` plus the unit's suffix.
  - The suffixes are `ms`, `s`, `m`, `h` and `d` for milliseconds, seconds,
    minutes, hours and days.
  - Examples: `format(5400, Seconds) = "1h30m"`, `format(1500,
    Milliseconds) = "1s500ms"`, `format(0, Minutes) = "0m"`,
    `format(-90, Seconds) = "-1m30s"`, `format(3, Days) = "3d"`.

### Kinds and rules (`src/rules/`)

```rust
pub enum FieldKind { Integer, Real, Text, Bool, Duration, Blob, Any }   // serde camelCase
pub struct AllowedValue { pub value: DbValue, pub label: String }      // label defaults to the value text
pub struct FieldRule {
    pub kind: FieldKind,
    pub nullable: bool,
    pub unit: Option<DurationUnit>,  // Some iff kind == Duration
    pub min: Option<String>,         // integer/real: canonical decimal; duration: canonical duration text
    pub max: Option<String>,
    pub min_length: Option<u32>,
    pub max_length: Option<u32>,
    pub pattern: Option<String>,     // unanchored source, as written in the config
    pub allowed: Option<Vec<AllowedValue>>,
    pub empty_is_null: bool,
}
pub enum FieldIssueCode {
    Required, WrongType, NotInteger, NotReal, NotBool, NotDuration, DurationPrecision,
    BelowMin, AboveMax, TooShort, TooLong, PatternMismatch, NotAllowed,
    // database-dependent; never produced by validate, used by later milestones:
    Unique, ReferenceMissing, NotEditable, UnknownField,
}
pub struct FieldIssue { pub code: FieldIssueCode, pub message: String, pub limit: Option<String> }
pub struct FieldError { pub column: String, pub issues: Vec<FieldIssue> }
```

- All of these derive `Clone, Debug, PartialEq, Serialize, Deserialize,
  ts_rs::TS` with camelCase, and `Eq` where possible. `FieldIssueCode`
  serializes camelCase (`"belowMin"`).
- `limit` carries the violated bound as text: `"100"`, the pattern, the
  canonical duration bound, or the unit name (`"minutes"`) for
  `durationPrecision`. Otherwise it is `None`.
- `message` is an English sentence for logs and fallback. The UI may show
  its own copy per code.
- A `FieldRule` may hold a compiled pattern cache privately, but its
  serialized form is exactly the fields above.

### `validate`

```rust
pub fn validate(rule: &FieldRule, input: &DbValue) -> Result<DbValue, Vec<FieldIssue>>;
```

The checks run in this order. Each step gives the normalised value on
success.

1. **Null** (`{"type":"null"}`) → `Ok(Null)` if `nullable`, else
   `[Required]`.
2. **Kind/shape**: the input variant must fit the kind.
   - integer kind takes `integer`; real takes `real`; text takes `text`;
   - bool takes `integer`; duration takes `duration`.
   - Anything else, including any input for `blob`/`any`, is
     `[WrongType]`, and validation stops.
3. **Integer**: the grammar is `^[+-]?[0-9]+$` (no spaces), within `i64`.
   Otherwise `[NotInteger]`, and stop.
   - Normalised: canonical decimal (no `+`, no leading zeros, `-0` → `0`).
   - Then `BelowMin`/`AboveMax` (compared as integers) and `NotAllowed`
     (compared as canonical values).
4. **Real**: the grammar is
   `^[+-]?([0-9]+(\.[0-9]*)?|\.[0-9]+)([eE][+-]?[0-9]+)?$`, parsed to a
   **finite** `f64`. Otherwise `[NotReal]`, and stop.
   - Normalised: the input string unchanged, so TypeScript never has to
     reproduce Rust's float formatting.
   - Then `BelowMin`/`AboveMax` (compared as `f64`).
5. **Bool**: the canonical integer must be `0` or `1`, or `[NotBool]`.
   Normalised: `"0"`/`"1"`.
6. **Duration**: `duration::parse(text, unit)`.
   - `Grammar` and `Overflow` give `[NotDuration]`; `Precision` gives
     `[DurationPrecision]` with `limit` = the unit name. Either way, stop.
   - Normalised: `Duration(format(count, unit))`.
   - Then `BelowMin`/`AboveMax`, comparing counts. The bounds are parsed from
     the rule's canonical text.
7. **Text**: if `empty_is_null` and `nullable` and the text is `""`, the
   result is `Ok(Null)`. Otherwise collect, in this order:
   - `TooShort`, `TooLong` (length in Unicode scalar values,
     `chars().count()`);
   - `PatternMismatch` (whole value, compiled as `^(?:p)$`);
   - `NotAllowed` (exact match).

   Return everything collected. No trimming.

Issues are returned in the order the `FieldIssueCode` variants are declared.

### Shared vectors (`examples/dbmanager/validation-cases.json`)

```json
[{ "name": "integer below min", "rule": { …FieldRule… },
   "input": {"type":"integer","value":"-1"},
   "ok": null, "issues": ["belowMin"] }, …]
```

Each case has either `"ok": <normalised DbValue>` with `"issues": []`, or
`"ok": null` with the expected codes. A case may also give `"limits"`, the
expected `limit` strings in the same order.

There must be at least **80 cases**, covering:

- every code `validate` can produce, and every kind;
- each normalisation rule: `+7`, `007`, `-0`, `.5`, `5.`, `1e3`, `1e400`,
  and `"0"`/`"1"`/`"2"` for bool;
- `empty_is_null` on and off, nullable and not;
- lengths counted in characters: include `"é"`, an emoji and a combining
  sequence;
- pattern anchoring (`"ab"` against `a` fails);
- `allowed` integers and texts;
- `i64` limits (`9223372036854775807` is ok, `9223372036854775808` gives
  `notInteger`).

At least **20 of the cases are durations**:

- each unit;
- the bare integer form;
- `1h30m` and `1h 30m` normalising to the same canonical text;
- negative values and zero;
- `ms` with unit seconds (`1500ms` → `durationPrecision`, limit
  `"seconds"`; `2000ms` → `"2s"`);
- out-of-order suffixes, a repeated suffix, a double space, leading or
  trailing spaces, an uppercase suffix and a decimal, each giving
  `notDuration`;
- overflow (`notDuration`);
- `belowMin`/`aboveMax` with canonical duration limits;
- days (`2d` with unit hours → `"2d"`, from 48 hours).

Patterns used in the vectors must mean the same in Rust `regex` and in JS
`RegExp` with the `u` flag.

## Acceptance criteria

- Every case in `validation-cases.json` passes in Rust: the same `ok` value,
  or the same codes in the same order (and the same limits, when given).
- `DbValue` serializes to exactly the six JSON shapes above (tests compare
  strings) and deserializes them back.
- `DbValue` from each SQLite storage class, read from a temp database,
  matches. A 1 MiB blob becomes `{"type":"blob","value":{"size":1048576}}`.
- `to_sql` of a validated value round-trips through a temp database
  (`INSERT` then `SELECT typeof(x), x`):
  - integer, bool and duration store `integer` (a duration stores its count
    in the unit);
  - real stores `real`;
  - text stores `text`.
- `duration::parse` and `format` round-trip for every unit over a range of
  values including 0, negatives and `i64::MIN`/`MAX` counts where
  representable. `format` never emits a component smaller than the unit.
- `generated_types_are_current` and `generated_types_have_no_bigint` pass.
  The new files exist in `lib/generated/`, and no existing generated file
  changed.
- fmt, clippy pedantic and `cargo test --workspace` pass.

## Out of scope

- Inferring kinds and resolving `FieldRule`s from config and schema,
  including checking duration bounds against the unit: M5.
- Database-dependent issues (`unique`, `referenceMissing`, …), produced by
  later milestones.
- The TypeScript mirror, a later milestone that consumes the vectors.

## Risks

- `regex` and JS `RegExp` differ on exotic syntax. Keep the vectors in the
  common subset, and keep the doc's warning.
- Rust's `str::parse::<f64>` accepts more than the grammar (`inf`, `nan`).
  Check the grammar first.
- Duration arithmetic must not overflow before the check. Use `i128` for the
  millisecond total.
