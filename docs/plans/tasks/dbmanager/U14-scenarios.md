## Goal

Register the Database Manager's 25 screenshot scenarios in the GPUI

## Context

The user manual's images are generated by the Rust harness from the real
GPUI app with fixture backends. The Database Manager's fixture backend
(`apps/filemanager/src/tools/dbmanager/fixtures.rs`) wraps a real tool core
over a database built from `examples/dbmanager/schema.sql` in a temp dir
it creates, with `examples/dbmanager/example.toml` as the config, and shows
fake display paths. States (M12a–M12d, R6): nothing open, example open,
config missing, config fail-closed (syntax error), state warning, dirty
draft, validation error, conflict, create form, saved with backup, staged
adds/removes with link fields, link conflict, delete confirmation, blocked
delete (publisher editable with delete allowed), diagnostics (one error,
one warning), a config edit that makes book `pages` read-only.

Harness (gpui-migration M4, `apps/filemanager/src/shoot/`): `Scenario {
name, size, setup: fn(&mut AppSetup), steps, clip }`;
`Step::{SelectTool(ToolId::Dbmanager), Click(sel), Keys(..), Type(..),
DragEnter, Drop, Watcher(ToolId), Call(fn(&mut Window, &mut App)),
WaitIdle, Wait(ms)}`. Use `Call` to drive the model directly where clicking
would take many steps (find the model through the tool registry as the
other scenario files do). Close prompt: `Shell::request_close(window, cx)`
(R7). **If a fixture state or harness feature listed here is missing when
you start, stop and report the gap.** Patterns:
`src/shoot/scenarios/{pipeline,schedule,tarpack}.rs`.

Selectors (dbmanager U2–U12): `db-open`, `db-recent`, `db-table-<name>`,
`db-list-row-<n>`, `db-follow-<field>`, `db-change-<field>`,
`db-picker-search`, `db-save`, `db-delete`, `db-refby-<relation>`,
`db-shortcuts`, `db-edit-config`, `db-config-problems`.

Every scenario starts with `SelectTool(ToolId::Dbmanager)`.

**Scenario tags (planner rule, 2026-11-22, after M4).** The screenshot
harness resolves `Step::Click` and `Scenario::clip` only by `.tag("<name>")`
names (`apps/filemanager/src/app/probe.rs`); GPUI's debug selectors cannot be
read outside `VisualTestContext`, so they do not work in the harness. Every
element a scenario clicks or clips therefore carries `.tag("<name>")` as the
**outermost (last) call of its builder chain**, using the names this plan
lists (where this plan says "debug selector", read "tag"). If a
`VisualTestContext` view test also clicks the element, add
`.debug_selector(..)` with the same name as well.
