Status: approved (2026-11-21)
Project: gpui-migration   Depends on: U11 (landed), U8 (landed), M4 (landed), and the harness's `Scenario::clip` (planner request R1, added to M4)

## Goal

Register the nineteen Tar Packager scenarios of the user manual in the GPUI
screenshot harness and judge the renders against today's images.

## Context

The manual's images will be generated by the Rust harness from the real
GPUI app with fixture backends (M8 replaces the PNGs). Same layout and
token colours as today (±1 per channel, geometry within about 2 px; text
widths may differ). CI never fails on image differences; a scenario that
cannot run fails the job.

Harness (M4, `apps/filemanager/src/shoot/`): `Scenario { name, size,
setup: fn(&mut AppSetup), steps, clip }`, where `clip: Option<&'static str>`
crops the PNG to that tag's bounds (`.tag("<name>")`) (added on the planner's
request R1; **if `clip` does not exist when you start, stop and report the
gap**). `Step::{SelectTool(ToolId), Click(sel), Keys("ctrl-alt-shift-d"),
Type, DragEnter(&[paths]), Drop(&[paths]), Watcher(ToolId), Call(fn),
WaitIdle, Wait(ms)}`. Pattern: `src/shoot/scenarios/{pipeline,schedule}.rs`.
Fixtures (M7a/M7b, `tools/tarpack/fixtures.rs`, through
`FixtureId::Tarpack(..)`): the manifest states (empty, loaded, partial,
ready, missing, errors, withheld, recent list), drop outcomes for the
dropped and withheld shots, and build fixtures (slow build with progress at
fixed points, output exists, full and partial summaries). The fixture
manifest has today's mock's 5 entries (the example's 3 plus `gateway-ca` and
`gateway-unit`, with mock.js's diagnostics; M7a's review follow-up), so the
shots match the reference geometry. **Row order differs:** the fixture rows follow
`example.toml` (bin, conf, start), not the mock's (bin, start, conf), so the
CRLF → LF marker and the Missing row sit on different rows than in today's
`tarpack-*.png`. Do not treat that as a regression in row-wise comparisons. The gateway
manifest is `C:\Packages\gateway\manifest.toml`; dropped paths below are
fake and never touched.

Selectors (U9–U11): `tarpack-recent`, `tarpack-shortcuts`, `tarpack-build`,
`tarpack-header`, `tarpack-build-bar`, `tarpack-build-result`.

**Scenario tags (planner rule, 2026-11-22, after M4).** The screenshot
harness resolves `Step::Click` and `Scenario::clip` only by `.tag("<name>")`
names (`apps/filemanager/src/app/probe.rs`); GPUI's debug selectors cannot be
read outside `VisualTestContext`, so they do not work in the harness. Every
element a scenario clicks or clips therefore carries `.tag("<name>")` as the
**outermost (last) call of its builder chain**, using the names this plan
lists (where this plan says "debug selector", read "tag"). If a
`VisualTestContext` view test also clicks the element, add
`.debug_selector(..)` with the same name as well.

## Acceptance criteria

- `--only tarpack-` writes nineteen PNGs (full ones at 1366×800, the four
  clipped ones at their region's size) and exits 0 on Windows CI; two runs
  byte-identical (reported).
- Side by side with today's images: same regions, positions, colours; the
  accepted differences only (fixed overlay shadows; fixed two-line rows;
  focus ring style; text widths).
- fmt; clippy pedantic with and without `--features shoot`.

## Tests proving completion

scenario's steps end idle, except `tarpack-building`, which ends with the
progress visible; the menu, popover, overlay or dialog is open where the
