### The human's decisions this text records

- **Accessibility (approved replacement).** "Keyboard operation and labels
  are requirements. Every interactive element is keyboard reachable and
  labelled (a visible label, or a tooltip for an icon-only control).
  Screen-reader support, axe-style audits, high contrast and text scaling
  are not requirements."
- **Paths (approved rewording).** "Paths are handled as the platform's path
  type, not as display strings. Code that renders a path does not assume it
  is valid UTF-8. Exception: GPUI's file dialogs and Explorer drop deliver
  only names that are valid Unicode. A name they cannot deliver is reported
  to the user, never skipped silently, and the dialog's starting directory
  falls back to the nearest valid-Unicode ancestor. Paths from every other
  source stay exact."
- **`impeccable`:** kept (enabled in `.claude/settings.json`) for `shape`
  (design briefs) and `critique` (of generated screenshots) only; `audit`,
  `polish` and the detectors are removed from the UI roles.
- **Screenshots:** generated by `filemanager-shoot` (feature `shoot`, dev
  profile, Windows at 100% scale); CI uploads them and never fails on image
  differences; capture never ships in the release exe.
- **Fonts:** Cascadia Mono (OFL) is embedded; Segoe UI is the system UI
  font.
- **Windows 11 only;** Linux CI builds and runs headless tests (no Linux
  window backend).
- **Dependencies:** exact pins of `gpui-pre`, `gpui-pre-platform`,
  `gpui-component`, `gpui-kit-assets`; committed `Cargo.lock`; `--locked`;
  no vendoring; an upgrade is its own reviewed change.

### "Adding a tool" (rewrite)

1. A crate `crates/fm-<tool>` with no UI dependency and `[lints] workspace = true`;
   its session logic in `src/session/`, testable without the app.
2. `apps/filemanager/src/tools/<tool>/`: `backend.rs` (trait, one method per
   operation, and the real impl over the crate's `Core`), `model.rs` (the
   view-model entity), `text.rs` (copy), `fixtures.rs`
   (`#[cfg(any(test, feature = "shoot"))]`), `mod.rs` (`ToolHooks`), and
   `view/` (UI).
3. A `ToolId` variant and an entry in `tools::build`; fixture ids in
   `BackendSet`.
4. Its screenshot scenarios in `src/shoot/scenarios/`.
5. Persisted state under the tool's own namespace in `fm-core`'s `Store`.
