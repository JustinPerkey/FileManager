# U8 — Schedule Creator screenshot scenarios

Status: approved (2026-11-21)
Project: gpui-migration   Depends on: U7 (landed), U6 (landed), M4 (landed)

## Goal

Register the five Schedule Creator scenarios of the user manual in the
GPUI screenshot harness and judge the renders against today's images.

## Context

The manual's images will be generated by the Rust harness from the real
GPUI app with fixture backends (M8 replaces the PNGs later). Same layout
and token colours as today (±1 per channel, geometry within about 2 px;
text widths may differ). CI never fails on image differences; a scenario
that cannot run fails the job.

Harness API (M4, `apps/filemanager/src/shoot/`): `Scenario { name, size,
setup: fn(&mut AppSetup), steps }`, `Step::{SelectTool(ToolId), Click(sel),
Keys, Type, DragEnter, Drop, Watcher(ToolId), Call(fn), WaitIdle, Wait(ms)}`.
Pattern to follow: `src/shoot/scenarios/pipeline.rs` (U6). Fixtures (M6,
`tools/schedule/fixtures.rs`): `FixtureSchedule::{empty, ready, bad}` and an
apply outcome `ParseNotImplemented` (the fixture's default), selected through
`FixtureId::Schedule(..)` in `AppSetup`. Selectors (U7): `schedule-apply`,
`dialog-confirm`. Command:
`cargo run -p filemanager-gpui --features shoot --bin filemanager-shoot -- --out shots --only schedule-` for light, and the same with `--dark --prefix dark-` for dark (without a prefix, the dark run overwrites the light PNGs).

All at 1000×700; every scenario starts with `SelectTool(ToolId::Schedule)`.

| Scenario | Fixture | Then | Today's image shows |
|---|---|---|---|
| `schedule-empty` | `empty()` | `WaitIdle` | both inputs empty; the reason under Add to XML… |
| `schedule-ready` | `ready()` | `WaitIdle` | both paths set; Add to XML… enabled |
| `schedule-bad` | `bad()` (a relative text path) | `WaitIdle` | the slot error and red border |
| `schedule-confirm` | `ready()` | `Click("schedule-apply")`, `WaitIdle` | the confirmation naming both paths |
| `schedule-notimpl` | `ready()`, apply → `ParseNotImplemented` | `Click("schedule-apply")`, `WaitIdle`, `Click("dialog-confirm")`, `WaitIdle` | the error banner saying it is not written yet and nothing changed |

**Scenario tags (planner rule, 2026-11-22, after M4).** The screenshot
harness resolves `Step::Click` and `Scenario::clip` only by `.tag("<name>")`
names (`apps/filemanager/src/app/probe.rs`); GPUI's debug selectors cannot be
read outside `VisualTestContext`, so they do not work in the harness. Every
element a scenario clicks or clips therefore carries `.tag("<name>")` as the
**outermost (last) call of its builder chain**, using the names this plan
lists (where this plan says "debug selector", read "tag"). If a
`VisualTestContext` view test also clicks the element, add
`.debug_selector(..)` with the same name as well.

- Side by side with today's images: same regions, positions, colours.
- fmt; clippy pedantic with and without `--features shoot`.
